### 2. Datetime Compatibility
**Status:** ✅ COMPLETE  
**Fix:** Changed `datetime.UTC` to `timezone.utc`

Python's `from datetime import datetime` imports the class, not the module.  
`datetime.UTC` only exists on the module in Python 3.11+.  
Solution: Import `timezone` and use `timezone.utc` (works in all Python 3.x versions)

## ⚠️ POTENTIAL ISSUES TO MONITOR

### 1. Primary Key Structure
**Firebase:** Auto-generated document IDs (random strings)  
**Supabase:** UUID v4 generated by app code

**Current Implementation:** ✅ CORRECT
- Using `uuid.uuid4()` to generate IDs
- Passing `id` field explicitly in INSERT
- Supabase table should have `id UUID PRIMARY KEY`

**What to Check:**
```sql
-- In Supabase SQL Editor, verify:
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'schedules' AND column_name = 'id';

-- Expected: id | uuid | NO
-- If id is SERIAL/INTEGER with auto-increment, this will cause conflicts!
```

### 2. Field Name Conventions
**Firebase:** Can use any field names (camelCase common)  
**Supabase:** PostgreSQL convention is snake_case

**Current Implementation:** ✅ CORRECT
- Backend uses `subj_code`, `subj_name`, `school_year` (snake_case)
- Frontend receives camelCase (`subjCode`, `subjName`, `schoolYear`)
- Conversion happens in response mapping

**Field Mapping:**
| Frontend (camelCase) | Database (snake_case) |
|---------------------|---------------------|
| `subjCode` | `subj_code` |
| `subjName` | `subj_name` |
| `schoolYear` | `school_year` |
| `prof` | `prof` (unchanged) |
| `room` | `room` (unchanged) |

### 3. Timestamp Format
**Firebase:** Uses `datetime.utcnow().isoformat()` or Firestore SERVER_TIMESTAMP  
**Supabase:** PostgreSQL TIMESTAMPTZ or ISO 8601 strings

**Current Implementation:** ✅ CORRECT
- Using `datetime.now(timezone.utc).isoformat()`
- Returns format: `"2026-08-25T22:45:53.123456+00:00"`
- Supabase stores as TIMESTAMPTZ

**What to Check:**
```sql
-- Verify created_at column type
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'schedules' AND column_name = 'created_at';

-- Expected: created_at | timestamp with time zone
```

### 4. Null vs Empty String Handling
**Firebase:** Treats missing fields as null  
**Supabase:** PostgreSQL differentiates null vs '' (empty string)

**Potential Issue:** If Supabase columns have `NOT NULL` constraints but code tries to insert `None`

**Current Implementation:** Mixed
```python
'prof': data.get('prof', ''),      # Defaults to '' (GOOD)
'room': data['room'],               # Could be None if missing (CHECK)
```

**Recommendation:** Add defensive defaults:
```python
'prof': data.get('prof') or '',
'room': data.get('room') or 'TBA',
'section': data.get('section') or 'N/A',
```

### 5. Transaction Rollback Support
**Firebase:** Limited transaction support  
**Supabase:** Full PostgreSQL ACID transactions

**Current Implementation:** No explicit transactions  
**Recommendation:** Wrap multi-step operations in try-except with rollback:
```python
try:
    # Delete old schedules
    supabase.table('schedules').delete().eq('semester', sem).execute()
    
    # Insert new schedules
    for sched in new_schedules:
        supabase.table('schedules').insert(sched).execute()
except Exception as e:
    # In Supabase, use .rollback() if using transactions
    logger.error(f"Transaction failed: {e}")
```

### 6. Query Performance (Indexes)
**Firebase:** Automatic indexing  
**Supabase:** Manual index creation for performance

**Recommendation:** Add indexes for frequently queried fields:
```sql
-- In Supabase SQL Editor
CREATE INDEX IF NOT EXISTS idx_schedules_prof ON schedules(prof);
CREATE INDEX IF NOT EXISTS idx_schedules_semester ON schedules(semester);
CREATE INDEX IF NOT EXISTS idx_schedules_school_year ON schedules(school_year);
CREATE INDEX IF NOT EXISTS idx_schedules_day ON schedules(day);
```

### 7. Array and JSON Fields
**Firebase:** Native support for nested objects  
**Supabase:** Uses JSONB type

**Current Status:** No array/JSON fields in schedules table  
**If Added:** Use PostgreSQL JSONB operators:
```python
# Firebase
schedule['metadata'] = {'tags': ['important', 'urgent']}

# Supabase - same, but query differently:
supabase.table('schedules').select('*').contains('metadata', {'tags': ['important']})
```

## 🆘 TROUBLESHOOTING COMMON ISSUES

### Issue: "duplicate key value violates unique constraint"
**Cause:** UUID collision (extremely rare) or manual ID reuse  
**Fix:** Ensure using `str(uuid.uuid4())` for all new records

### Issue: "null value in column violates not-null constraint"
**Cause:** Required field missing in INSERT  
**Fix:** Add default values or make column nullable in Supabase

### Issue: "column does not exist"
**Cause:** Field name mismatch (camelCase vs snake_case)  
**Fix:** Use snake_case in database, convert to camelCase in response

### Issue: Schedules not updating in real-time
**Cause:** Frontend caching old Firestore data  
**Fix:** Clear browser localStorage, hard refresh (Ctrl+Shift+R)

### Issue: CHE model errors persist
**Cause:** Old model names cached or API key invalid  
**Fix:** Restart Flask server, verify GROQ_API_KEY in .env
